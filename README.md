# Catherina

**适用于 Mengka NT 的 QQ 助手，全部功能免费。**

把群管理、消息回复、菜单、群发和定时任务放在一个管理页面里。支持同时接入多个 QQ，每个 QQ 分别设置主人、功能、菜单和任务，切换账号时配置互不影响。

Catherina 与萌卡分别启动，通过 WebSocket 连接。支持 Windows x64、Linux x64 和 Linux ARM64。

[下载安装包](https://github.com/Jay1023CN/Mengka-NT-plugins/releases) · [反馈问题](https://github.com/Jay1023CN/Mengka-NT-plugins/issues)

## 可以做什么

| 分类 | 功能 |
| --- | --- |
| 消息与群发 | 向白名单群发送消息，设置循环群发、每天定时群发，代发好友或群消息 |
| 菜单与回复 | 自定义菜单正文、触发词和回复内容，多行前后缀，问答库，触发人员名单 |
| 群聊管理 | 成员禁言、全体禁言、踢人、群公告、成员查询、专属头衔、群打卡 |
| 聊天互动 | 艾特回复、戳一戳回复、消息表情回应、名片点赞、随机回话、私聊互动天数与续火提醒 |
| 消息辅助 | 撤回消息文本还原、闪照保存、消息与事件记录、好友及入群申请处理、红包领取 |
| QQ 与空间 | 好友备注、个性签名、账号状态、空间动态点赞评论、定时说说、免费等级任务查询与执行 |
| 实用工具 | 网易云点歌、随机字母、字数统计、文本反转、全角与半角转换 |
| 通知与反馈 | 上线通知、自定义通知对象与内容、向主人转交问题反馈、插件公告与版本更新入口 |

功能可以按账号单独开关，聊天指令的触发词也可以修改。群管理操作使用当前 QQ 的群权限；撤回还原只处理插件已经收到并缓存的消息文本。

## 下载与启动

先准备好正在运行的 [Mengka NT](https://github.com/Carlor-Official/Mengka-NT)，再下载对应系统的 Catherina 安装包。

| 系统 | 选择的文件 | 启动程序 |
| --- | --- | --- |
| Windows x64 | 文件名包含 `windows-amd64` | `Catherina.exe` |
| Linux x64 | 文件名包含 `linux-amd64` | `Catherina` |
| Linux ARM64 | 文件名包含 `linux-arm64` | `Catherina` |

把安装包解压到一个可写的文件夹。ZIP 用于下载安装，运行时使用解压后的程序。

已有用户更新时，先退出程序，再替换对应的可执行文件；保留原来的数据目录。

### Windows

双击 `Catherina.exe`，浏览器会打开管理页面。程序窗口需要保持运行。

### Linux

进入解压后的目录执行：

```sh
chmod +x Catherina
./Catherina
```

在运行程序的电脑上打开 **http://127.0.0.1:18096**。

管理页面已经内置，无需另外安装 Go、Node.js 或 WebView2。使用管理页面、下载安装包均不需要登录 GitHub。

## 首次连接

1. 打开管理页面，设置一个至少 8 位的管理密码。
2. 在萌卡的“插件对接”中启用正向 WebSocket，创建服务令牌，并允许所需消息和事件。
3. 进入 Catherina 的“连接与更新”，填写 WebSocket 地址及服务令牌，点击“保存并连接”。
4. 从左侧选择要管理的 QQ，在“账号设置”中填写主人 QQ。
5. 到“功能与指令”开启需要的功能，再配置菜单、白名单和自动任务。

连接后可以刷新 QQ 列表。切换 QQ 后，页面显示的是该账号自己的配置；同一 QQ 使用不同协议时也分别保存。

## 管理页面怎么用

| 页面 | 用途 |
| --- | --- |
| 总览 | 查看当前账号、功能状态和插件公告 |
| 功能与指令 | 开关功能，搜索功能，修改指令触发词，设置触发人员 |
| 菜单内容 | 编辑菜单正文、前后缀、自定义菜单和各项功能的回复内容 |
| 问答与白名单 | 添加问答，维护参与群发的群号 |
| 自动任务 | 添加、编辑、暂停或删除循环群发、定时群发、定时说说 |
| 账号设置 | 设置主人、回复文案、上线通知和其他账号选项 |
| 连接与更新 | 管理萌卡连接，查看版本信息 |
| 接口调试 | 发送 HTTP 请求并查看返回内容 |
| 监控记录 | 查看当前账号命中的监控消息，可一键清空；记录保留 7 天 |

功能开关点击后保存。菜单和其他文本编辑完成后，点击“保存修改”，也可以按 **Ctrl+S**。

### 配置一条自定义菜单

进入“菜单内容”，点击“添加菜单”，填写触发词和实际回复内容。可以设置仅好友触发，或允许好友和群聊触发；需要限制使用人员时，填写触发人员 QQ。

菜单正文、前缀和后缀都可以直接换行，也可以插入变量。例如：

```text
你好，【发送者QQ】
这里是【插件名字】
当前时间：【现行时间】
```

| 变量 | 含义 |
| --- | --- |
| `【发送者QQ】` | 发送这条消息的人 |
| `【框架QQ】` | 当前机器人 QQ |
| `【群号】` | 当前群号，私聊时为空 |
| `【插件名字】`、`【插件版本】` | 插件名称与版本 |
| `【现行时间】` | 当前日期和时间 |
| `【10位时间戳】`、`【13位时间戳】` | 秒级、毫秒级时间戳 |
| `【换行符】`、`【空格】` | 插入换行或空格 |

### 配置群发和定时任务

先在“问答与白名单”添加群号，并开启对应群的群发开关。然后到“自动任务”选择任务类型、填写内容及时间，保存并启用。

群发仅面向当前账号已启用的白名单群。每天定时任务使用程序所在电脑的本地时间；任务可以单独暂停，保存后重启仍在。

## 常用聊天指令

以下是默认触发词，修改过触发词后请使用自己的设置。部分操作仅主人或已授权人员可用。

首次使用可以发送 `初始化配置` 自动生成一份完整菜单，不会改动其他账号设置。之后发送 `总菜单`（旧指令 `菜单` 仍可用）查看当前菜单。菜单按功能分组，并列出该账号已开启的指令、参数用法和自定义触发词；`搜索命令 关键词` 可以查具体指令。

| 想做什么 | 发送内容 |
| --- | --- |
| 初始化默认菜单（只补菜单，不改其他设置） | `初始化配置` |
| 查看完整功能菜单 | `总菜单` 或 `菜单` |
| 查找相关命令 | `搜索命令 群发` |
| 查看账号状态 | `账号状态` |
| 添加群发目标 | `群发 添加 群号` |
| 向白名单群发消息 | `群发 今天的通知内容` |
| 添加一条问答 | `问答 添加 你好\|你好，有什么可以帮你？` |
| 点歌 | `点歌 歌名` |
| 在当前群打卡 | `打卡` |
| 给指定 QQ 名片点赞 | `点赞 QQ 次数` |
| 查看免费等级任务 | `加速` |

## 数据保存

账号配置、菜单、问答和任务保存在本机。默认数据目录：

- Windows：`%APPDATA%\Catherina-Mengka`
- Linux：`~/.config/Catherina-Mengka`；设置了 `XDG_CONFIG_HOME` 时使用对应目录。

更换电脑前，先退出程序，再备份整个数据目录。

## 更新源与离线环境

程序每 3 小时读取一次更新清单 `release.dat` 和版本策略 `state.dat`，两个文件都在公开仓库里，只有几百字节。托管在萌卡里运行时不会自动下载安装包，读取它们只用于确认版本和展示公告。

服务器访问不了 GitHub 时不用做任何配置：程序会自动改用公共 CDN 镜像（jsDelivr 的 `cdn`、`fastly`、`gcore` 三个节点），它们回源同一个公开仓库，作者发布时不需要额外同步。哪个源能用完全由程序判断，切换到镜像时日志会出现一行“GitHub 直连不可用，更新源已切换到 …”。

只有当你想强制走自建源或内网静态目录时，才需要设置环境变量。设置后程序只认这一个地址，不再自动兜底：

```sh
export CATHERINA_FEED_BASE="https://mirror.example.com/mengka/"
```

萌卡托管下写在框架服务的启动环境里，例如 systemd：

```ini
[Service]
Environment="CATHERINA_FEED_BASE=https://mirror.example.com/mengka/"
```

地址要求：

- 必须是 https，只有 `127.0.0.1`、`localhost` 这类本机回环允许 http。
- 指向存放这两个文件的**目录**，结尾写不写 `/` 都可以；不能带账号密码、`?` 查询串或 `#` 片段。
- 配置无效时程序直接报错退出，不会悄悄改用默认源。是否生效看管理页“连接与更新”，接口 `GET /api/service` 里的 `feed_base` 是当前生效源，`feed_sources` 是本次会依次尝试的全部地址。

换源不会降低安全性：文件仍要解密并用发布公钥验签，程序还会拒绝回退或重复编号的策略，镜像只能提供同一份已签名内容。

完全离线的机器可以手工投喂策略：在有网机器下载 `state.dat`，重命名为 `state-cache.dat`，以 600 权限放进数据目录，然后启动程序读取。策略本身最长 30 天有效，到期需要重新投喂，否则机器人功能会暂停。

安装包下载地址固定指向 GitHub Releases（清单里的地址会逐一校验），因此手动模式的自动升级仍需能访问 Releases；萌卡托管下由框架重新导入安装包，不受影响。

## 常见问题

**连不上萌卡或没有 QQ 列表？**

确认萌卡已经运行，QQ 已登录，正向 WebSocket 已开启。填写的是 WebSocket 地址，而非萌卡网页地址；同时检查服务令牌和事件权限，连接后刷新 QQ 列表。

**指令没有回复？**

先确认左侧选中了正确的 QQ，再检查功能开关、触发词和触发人员权限。群发还需要配置白名单；群管理需要当前 QQ 具备相应权限。

**Linux 程序运行在远程电脑上，怎么打开管理页面？**

在自己的电脑建立 SSH 端口转发，把 `user@host` 改成远程电脑的登录账号和地址：

```sh
ssh -L 18096:127.0.0.1:18096 user@host
```

保持连接，再在自己的浏览器打开 **http://127.0.0.1:18096**。

**遇到问题怎么反馈？**

在 [Issues](https://github.com/Jay1023CN/Mengka-NT-plugins/issues) 写明插件版本、系统、出问题的操作和截图。请遮住截图中的管理密码与服务令牌。
